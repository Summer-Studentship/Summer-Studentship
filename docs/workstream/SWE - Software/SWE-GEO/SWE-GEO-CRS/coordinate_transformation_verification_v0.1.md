# Coordinate Transformation Verification

**Document ID:** `SWE-GEO-CRS-VER-v0.1`
**Work Package:** `SWE-GEO-CRS-WP1`
**Status:** Implemented G1 verification evidence

## Controls

The G1 checks use independent JSON controls in `tests/fixtures/geospatial/crs/controls/`:

- Zone X natural-origin and known-point controls for `EPSG:6668` to `EPSG:6678`;
- WGS84-to-metric sanity controls;
- vertical identity, unit/sign and authoritative-offset controls.

The controls are committed as fixture evidence and are not generated by the adapter path under test.

## Test Coverage

Ordinary builds exercise the method-neutral `tsunami_geo` contracts, validation and canonical serialisation without linking PROJ. CRS-enabled builds add `tsunami_geo_proj` tests for:

- runtime metadata and disabled network policy;
- known-point projected transformation;
- vector feature transformation preserving identities, schema and attributes;
- raster transformation planning with densified boundaries and no resampling;
- missing or unverified grid-resource rejection;
- public-boundary scans for native PROJ token leakage.

## Verification Commands

The implemented slice is verified with ordinary, geospatial and CRS-enabled GCC/Clang presets. The focused CRS check is:

```bash
build/linux-gcc-crs-test/tests/tsunami_tests "[crs]"
```

Architecture evidence is checked with the target, layer and interface policy validators. JSON schema and fixture files are checked with `python3 -m json.tool`.
