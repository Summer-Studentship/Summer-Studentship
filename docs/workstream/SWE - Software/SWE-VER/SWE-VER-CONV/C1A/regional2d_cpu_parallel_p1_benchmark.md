# C1A-P1 Regional2D CPU Parallel Benchmark

Generated by `tools/verification/convergence/c1a_p1_parallel_benchmark.py` on the frozen C1A-R4 h1000 Regional2D case.

## Scope

- Serial authority: `TSUNAMI_ENABLE_OPENMP=OFF` release `tsunami_r2d_case`.
- Parallel candidate: `TSUNAMI_ENABLE_OPENMP=ON` release `tsunami_r2d_case`.
- Frozen numerical inputs: accepted G6 terrain and coseismic source copied from C1A-R4.
- Mesh: `r4-h1000.msh`, 2420 active triangular cells.
- Simulated horizon: 1.0 s, 10 accepted steps.
- Excluded by design: finer h500/h450/h400/h300 ladder, temporal convergence, Local3D/OpenFOAM, observations, and calibration.

## Result

OpenMP output equivalence passed for `1,2,4,8` threads against the serial binary reference. Coupling samples/history were byte-numerically identical for the checked numeric fields; final solution snapshots differed by at most `4.29101199017623e-13`. Diagnostics integral columns had maximum absolute differences up to `1.4454126358032227e-06`, with maximum relative difference `2.590248675271578e-11`, consistent with floating-point reduction ordering.

Median wall-clock speedup was flat on this short h1000 benchmark:

- OpenMP 1 thread: `0.9985x`
- OpenMP 2 threads: `1.0051x`
- OpenMP 4 threads: `1.0054x`
- OpenMP 8 threads: `1.0038x`

The benchmark therefore verifies race-safe execution and numerical equivalence, but does not demonstrate material throughput scaling for this short workload. The detailed machine-readable record is `regional2d_cpu_parallel_p1_benchmark.json`; the scaling table is `regional2d_cpu_parallel_p1_scaling.csv`.

## Profiling Note

`gprof` was available in the environment, while `perf`, `valgrind`, and `hyperfine` were not. No instrumented component timer exists in the current solver, so this P1 record uses subprocess wall-clock time, child CPU time, peak RSS, solver step count, binary hashes, and output equivalence checks as the authoritative benchmark evidence.
